# CrossPlay parity and limits

Ported ChessCore legal generation, attack detection, castling, en passant, four promotions, reversible moves and FEN; ChessEngine material/piece-square evaluation, MVV/LVA selection ordering and alpha-beta negamax. The UI uses explicit search frames with source depth levels 1/3/4 and 60,000-node budget, processed in 24-operation callbacks; no coroutine or background task. Source tests compare search scores, chosen moves and node counts, not merely legal random moves. Threefold and fifty-move draws follow mate/stalemate priority. Exact FEN keys replace uint64 FNV because the shipped Lua integers are 32-bit.

Sticky heaps of at least 512 KiB use the original CrossPlay Toybox board: Jersey 10/14/20/30 masks, Celtic 48px/24px pieces, white-piece silhouette knockout, light dither, 9px board frame and corner brackets, legal-destination dots/capture corners, an outside selection frame, original-width captured strips, procedural gear and bottom status capsule. Original ChessPieces.h and font masks are repacked losslessly with hashes and MIT/OFL licenses. Portrait geometry matches ChessActivity.cpp; landscape selects the original smaller piece cut and compresses settings rows to keep them reachable. No bitmap is stretched. The intermediate 256–511 KiB path retains the previous bitmap interface; the existing below-256 KiB refusal and non-Sticky legacy dispatcher are unchanged.

The supported settings use the original full-page label/value style: New Game, Take Back, Opponent, Level, Play As, and Move Hints, plus the existing Find Hint and Save/Exit actions. The old mode cycle is retained: Computer/White, Computer/Black, P&P. Play As switches computer colour directly. Both keep the tested existing mid-game mode-change semantics rather than the original restart-on-close policy. Move-hint visibility lasts for the current app session; existing mode/level settings remain in the unchanged game journal. The original startup shelf menu, Nearby and face-to-face piece rotation are not implemented. No lifetime record is fabricated.

The move sheet reconstructs original-style SAN from the saved contiguous legal FEN history, including ambiguity, captures/en passant, castling, promotion, check and mate, without changing the engine or snapshot. It shows the recent full moves that fit; history still retains at most 100 plies and validates legal transitions on restore. Source-style captured counts derive from starting material versus visible material, including the source limitation that promotions can affect that inference. Promotion choices use the original piece masks. Explicit search frames, cancellation, undo, hints, check/turn and saved completed games remain. There is no clock or tournament-strength claim.

Tests use the committed Lua source with signed int32/float32 settings and only shipped host APIs. They are native adapters, not a firmware build. Read the independent test directory for exact source oracles, failure injection and measured memory. No firmware/SDK download, flash, commit, push or PR creation was performed.

CrossPlay gameplay is selected only when `smudge.get_device()` returns `"sticky"`. The simulator compatibility path and firmware without that API run the byte-identical original game from base `2c82f306`. Original modules, assets, callbacks and save APIs are preserved; the replacement core/journal is never loaded on that path.

All CrossPlay feature descriptions and limitations above apply to Sticky only. Legacy behavior (including pre-existing limitations) is intentionally unchanged elsewhere. Native adapters use the stock int32/float32 Lua configuration but host pointers and instrumentation differ from hardware. Full legacy trace comparisons use a 2 MiB host cap; separate 75 KiB observations compare the unchanged baseline and dispatcher candidate and do not claim hardware memory parity.


Presentation validation: `python3 test/chess_graphics/run.py` checks exact board geometry, supported settings through rendered targets, all four promotion choices and independent SAN fixtures in both orientations using the shipped int32/float32 Lua. `test/replacement_chess/run.py` retains the source-oracle engine checks, corrupt-history/journal validation, 75 KiB refusal and callback regressions including search/cancel/undo, mate, underpromotion, save/reopen and twelve reloads. Native capture adapters now replay actual font/piece masks; they are not physical e-ink screenshots. Integer-rounded glyph advances/no kerning and the documented UI differences prevent a claim of exact pixel parity.
