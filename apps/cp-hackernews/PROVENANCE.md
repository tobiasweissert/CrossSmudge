# Hacker News original presentation

The Sticky presentation adapts the actual native builders and typography from `ma-r-s/crossplay` at immutable `d3a49ce8e85f9bd0d3e0c774a54adc267fd7547b`: `HackerNewsScreens.cpp/.h`, the reader's document shape in `HackerNewsActivity.cpp`, and their direct Toybox/FreeInkUI collaborators. CrossPlay MIT notices remain in `LICENSE`.

The original binding is per view, not a generic Jersey body. List/Busy use `readingFaces()` (Jersey 10 count, Noto Serif 14 body, Jersey 30 title). The reader uses `readerFaces()` (Noto Serif 11 small, Noto Serif 14 body, Noto Serif Bold 16 title), including the original title-fitting ladder and page-label placement. `test/hackernews_original_ui/repack.py` losslessly repacks the full source ASCII/Latin-1 glyph repertoire, 12.4 advances, signed bearings and original 36×30 serif kerning matrices from immutable Git objects. `art/sources.json` records source/output hashes. Jersey and Noto notices are retained in `OFL-Jersey25.txt` and `OFL-NotoSerif.txt`.

`reader.lua`, `model.lua`, `cache.lua`, `json.lua`, `design.lua`, manifest, original Lato assets, IDs, caches and accepted main repairs stay unchanged. The entire baseline `presentation.lua` body remains byte-identical below a Sticky-only dispatch prefix. Non-Sticky/missing-device-API execution uses it directly; new fonts are not loaded there. The Sticky entry wrapper only handles local visual slices for the immutable controller's six-item page, then delegates to the original callbacks. It does not change fetching, parsing, retries, paging work admission, comment cursors, storage or limits.

The five original cuts and three kerning strings total 55,182 bytes, loaded once per Sticky VM. Reader text is visited with one bounded current line and only the visible page retained; no whole-article/thread line array or flattened duplicate is allocated. This preserves the accepted bounded streaming mechanism; it is not a physical speed or memory improvement claim.

## Exact evidence and bounded differences

Busy and ordinary Reader frames match independently rendered original native builders over the full image in both orientations. The two-row List matches outside the explicitly changed footer labels, including its original borders, Noto headlines and Jersey comment counts. Pixel references, model fields, source hashes and comparison scope are pinned under `test/hackernews_original_ui/reference/`; host adapters are not physical-device screenshots.

The current controller uses Firebase Top/New/Ask/Show plus its existing article service, not the original Algolia front-page/saved-library model. No Saved shelf, SAVE/UNSAVE action, unreadable verdict or offline-library promise is fabricated. The native two-segment footer therefore shows the current feed and a FEEDS door exposing all four existing destinations. The comment-count column retains the port's direct comments action; the title opens the article. Errors use actual current-provider messages instead of falsely promising a Saved library. Transport/cache/more-comments status occupies the otherwise empty gutter above the reader body, preserving all readable lines.

Threads use the original uppercase-author/quote-marker document hierarchy; existing self-post text is retained. Original typography omits the prior port's extra point/age labels while their checked model/cache values remain intact. Arbitrary Unicode outside the original cuts appears as explicit `[U+XXXX]` text using the licensed masks; exact provider bytes remain unchanged. The native sparse wrap index is not claimed: the Lua presentation retains the current bounded streaming approach and measures actual source glyphs.

These are explicit capability/runtime differences, not complete original-application or physical-device parity claims. Update files in place and preserve existing cache slots. No firmware change, cache deletion or save migration is required for this presentation-only change.
