# CrossPlay parity and limits

Ported exact repeated-letter scoring, monotonic keyboard marks, validated word submission, six-row win/loss rules, Gregorian day conversion, answer/archive formats, save replay, on-the-day statistics and streak semantics. Independent source tests exercise scoring, dates and statistics. Completed games are saved per date; typed rows resume. Journaled results retry failures and can be reconstructed from finished daily saves, preserving whether the result was reached on that day.

CrossPlay bundles NO word bank: native code downloads mfilej/wrdl data and NYT daily answers. This port does not bundle/relabel those third-party datasets or claim network refresh. It reads user-supplied wordle.ans (five uppercase bytes per day from 2021-06-19, dots for unknown days) and sorted wordle.words (five uppercase bytes per accepted word), first in the app directory then /.crosspoint/. Reads are bounded and seeked; dictionary capacity is 32,000 entries, dates/results are bounded to days 0..8191. Results store a leading day offset instead of thousands of zero bytes. In the replacement-only 75 KiB stress test, daily history spans at most 1,024 days; a larger existing journal or date expansion safely requires PSRAM while practice remains available. S3 supports the full 8,192-day span. Oversized stress-test histories are not loaded or overwritten. The shipped API has no HTTP facility used by this port. No Nearby or invented network APIs.

Without imported data, explicitly labeled Legacy practice uses the unchanged existing 3,103-word words.bin. Its hash and original provenance are retained; it is not the CrossPlay archive, NYT data, or an exhaustive English dictionary. The original upstream word-list origin is not recorded here, so no new content-license claim is made. The new rules reject guesses outside the selected dictionary (the answer itself is always accepted). Practice is an additional compatibility mode; CrossPlay itself is daily/archive only. Daily/previous/next date selection and daily totals/streak are provided; source multi-month archive grid and graphical distribution are not reproduced. The stock date API may return a fallback date without a validity flag: confirm device clock before daily play. No network freshness or on-device rendering claim.

Tests use the committed Lua source with signed int32/float32 settings and only shipped host APIs. They are native adapters, not a firmware build. Read the independent test directory for exact source oracles, failure injection and measured memory. No firmware/SDK download, flash, commit, push or PR creation was performed.

CrossPlay gameplay is selected only when `smudge.get_device()` returns `"sticky"`. Every other device (including X3, X4, X4 Pro and simulator), and firmware without that API, runs the byte-identical original game from base `2c82f306`. Original modules, assets, callbacks and save APIs are preserved; the replacement core/journal is never loaded on that path.

All CrossPlay feature descriptions and limitations above apply to Sticky only. Legacy behavior (including pre-existing limitations) is intentionally unchanged elsewhere. Native adapters use the stock int32/float32 Lua configuration but host pointers and instrumentation differ from hardware. Full legacy trace comparisons use a 2 MiB host cap; separate 75 KiB observations compare the unchanged baseline and dispatcher candidate and do not claim hardware memory parity.
