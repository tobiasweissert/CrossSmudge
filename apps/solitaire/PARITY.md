# Solitaire parity and limits

Sticky uses the original Jersey cuts, CardArt masks, slim black header with Undo/New, seven-column card geometry, native foundation order, draw-three waste fan, variable tableau fan, full selected-run outline, front door, record ornament and victory cascade. Shared card offsets drive pixels and direct touch selection. The native first open card retains its readable strip in crowded columns. Stock, selected card/run, destination, Undo and Finish use actual callbacks. The New header returns to the original table menu; unfinished replacement still requires confirmation to protect existing play.

Mapped original source comparisons require zero differences across complete 800×480 frames for fresh menu, initial board, valid crowded tableau, selected run, three-card waste, selected waste and victory. Real source builders, actual original Epd glyph measurement and original CardArt are compiled independently. Original Solitaire forces landscape. This port also offers a fitted portrait layout; its narrower cards, stacked menu ornament and shorter labels are explicit adaptations, not native pixel matches. Both orientations have actual callback captures. Hardware appearance remains unverified.

Core rules, shuffle/deal, undo encoding and two-slot game journal remain unchanged. The old app, assets and save paths run unchanged on non-Sticky devices. Sticky below the 512KiB UI gate loads `compact_app.lua`, the exact previous controller, before parsing the larger view. Existing old-save backup and readback checks remain. No installed save is deleted. The new UI record uses separate `ui-records-{1,2}.dat` files inside Solitaire's existing private directory; it counts only observed wins/abandoned deals, retains 1024 results as the original does, and does not invent pre-update totals. Failed writes preserve the previous valid slot. Core game persistence precedes result persistence. A failed record write may omit that result after restart; it does not replace game data.

The routine replacement suite checks source-oracle rules, journals, legacy import, direct touch, redraw/reopen, failure handling and capped memory. The production-pixel routine adds native comparison states, real shipped glyphs and actual compiled Sticky identity. Non-Sticky trace pairs and separate 75KiB observations distinguish preserved behavior from host hardware equivalence. SVG captures are supplementary and do not approve font pixels.
