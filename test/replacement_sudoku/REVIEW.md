# Independent rules and storage review

The CrossPlay source oracle and Lua implementation were inspected separately. The source engine's defining behavior is its ordered ten-technique solver, measured difficulty bands, and maximal rotational-pair carving. The previous generator removed random clues without checking uniqueness; seed 12345 at Hard reproduced a multiple-solution puzzle under an independent counter.

The replacement core agreed with the unmodified C++ source for 176 solver results and placement hints, including exact hardest-technique and step counts. Sixteen generator seeds reproduced the source clue patterns and solutions exactly, across all four difficulty bands. Independent MRV backtracking counted exactly one solution for each. No rules discrepancy was found in this comparison. This finite corpus does not prove every possible candidate configuration.

The save journal was reviewed for bounded reads, malformed envelopes, accidental execution of save content, interrupted writes, and legacy preservation. Every truncation and single-byte mutation of a newest-slot fixture recovered the older valid slot. Simulated failed and partial writes did not advance the transaction; the next open recovered the prior valid state. Legacy backups preserve bytes, including embedded NUL, and neither an oversized original nor an existing backup is overwritten. No journal defect was found in these cases.

The live firmware opens only base, table, string, math, and os libraries (`LuaRunner.cpp:139`); it does not open `coroutine`. This was reported before UI implementation so asynchronous generation cannot assume coroutine support. Absolute bounded reads of `/.smudge/saved_data/sudoku/state.dat` are supported by the live `read_file` binding; `smudge.load` would instead read the entire legacy file before Lua can validate its size.

Production callback tests then passed at 480×800 and 800×480: generation and cancellation, keypad notes, source-consistent hints, undo, a complete played game, save/resume, elapsed-time persistence, write debouncing, checksum-valid malformed save rejection, and twelve reloads. Review found and the author fixed an elapsed-time concatenation syntax error, zero-seed replay metadata mismatch, paused/generation time accounting, missing quiet-time persistence, and excessive clock-driven writes. Generation now uses an explicit resumable job, with a maximum of 128 fill probes or one clue-pair solve per call; completed jobs are idempotent and discarded jobs are collected.

The native adapter is not hardware. S3 tests enforce 2 MiB; the final runtime tests peaked at 336,825 bytes including test fixtures and closed with zero tracked bytes. The engine-only 75 KiB probe failed at 76,746 bytes. The deliberate unsupported-device bootstrap passed at 26,233 bytes without reading or writing saves. That safe screen is not C3 gameplay support.

The two SVG artifacts use actual production draw coordinates but approximate fonts and header/hint rendering. They are not framebuffer captures. The source's hold-to-pencil gesture cannot be emitted by the current Lua activity; the tested Notes button provides the reachable stock tap path. Per-level records, conflict display, hint interaction, and other UI differences must be stated in the app's parity document. Device performance and text legibility still require hardware verification.
