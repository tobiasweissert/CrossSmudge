# Accepted-body checksum handoff

The isolated staging candidate now optionally returns StageReceipt after successful sync and close only. It contains the selected numeric candidate slot, planned generation, payload length, and FNV-1a checksum accumulated over accepted input bytes. Every entry clears a supplied stale receipt. Rejected, cancelled, source-read, partial-mutation, sync, and close failures leave it invalid. The empty-body checksum is the FNV offset basis.

stage_receipt_test.cpp passes the receipt checksum directly to the real checkStaged implementation and confirms the candidate remains unsealed and unrecoverable. It injects failure at each mutating adapter call (including calls that mutate before reporting failure), source reads, and cancellation boundaries. It is registered in run_all.py for normal and ASan/UBSan execution; the full routine exits zero. RED is retained in stage-receipt-red.log; the missing StageReceipt interface caused the expected compile failure before implementation. Previous receipt evidence is preserved in pre-receipt-wiring-receipt.json.

This is synthetic-adapter, portable-candidate evidence, not SdFat or physical acceptance. The API4 target remains disabled. The receipt is not publication authority and does not prove durable SD persistence. No firmware, combined release, remote branch, or upstream PR was changed.

Preserve the previous selected slot and do not unlink or rename ambiguous files. Inject partial writes, sync, close, readback uncertainty and reopen faults before wiring a real pinned SdFat adapter.
