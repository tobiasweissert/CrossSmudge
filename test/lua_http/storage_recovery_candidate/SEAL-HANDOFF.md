# Versioned portable sealing candidate — not hardware enabled

`SealStage.h` adds fixed-slot record-v1 publication with `committed`, `not_committed`, and `commit_unknown` outcomes. It does not modify API4 or the published firmware. Caller retains the exclusive app lock across fresh recovery, admission, staging and sealing. Receipts must match freshly recovered next generation/inactive slot, and staged bytes must pass the existing read-only verification.

`SealFiles::openSeal` is an explicit new adapter requirement: open the existing file without truncation/creation or mutation on failure. Post-close reads must read reopened storage, not a stale writer buffer. These semantics are a contract for a future adapter, not a claim about SdFat.

Cancellation is admitted before metadata mutation; afterward it cannot return guaranteed no-change. Footer precedes header; both precede sync/close and complete recovery readback. Any failure from the first metadata-write attempt onward returns `commit_unknown`, even if later recovery can select a complete record. No erase, rename, rollback or automatic retry occurs. Caller must stop further writes on an unknown outcome and run explicit recovery; this candidate does not itself implement a persistent per-app uncertainty latch or Lua response contract.
