# Actual pinned FAT host qualification — downloads still disabled

This phase links the unmodified pinned SdFat `FatLib/*.cpp` and `common/*.cpp` into the recoverable-record candidate, rather than extracting one method or faking the filesystem. A synthetic sparse RAM block device is formatted as a 16 MiB FAT volume using the real `FatFormatter`. Test-only `SdFatFiles` uses real `FatFile` opens, truncation, seeking, reads, writes, sync and close. It is not a firmware adapter and is not enabled in API4.

The normal and ASan/UBSan runs pass: format/stage/seal/reopen; failures on each of two actual seal block writes, both without mutation and after a complete sector mutation with negative acknowledgement; fresh-volume remount with all former filesystem/writer caches abandoned; preservation and full readback of the previous generation. Four injected block-write failures per mode are exercised, not an exhaustive SD power-cut matrix. Seal failures correctly return `commit_unknown`.

Compilation uses the shipped `USE_BLOCK_DEVICE_INTERFACE=1`, `SPI_DRIVER_SELECT=3` and non-Arduino feature settings. A separate forced compatibility header supplies only a forward-declared print string helper, F macro and deterministic millis stub for the unused LFN collision path. The actual FAT/cache/file implementations are unedited. This is host FAT qualification, not SPI/SDMMC, target ABI, exFAT, physical SD or durability proof. The fixture intentionally precreates the two fixed slot files; missing-file versus I/O-error admission and production path confinement still require a production adapter.

`run_sdfat.py` pins the previously established FatFile.cpp SHA and records before/after hashes of all library source/header inputs and candidate inputs. `run_all.py` now invokes it after the six portable suites; the complete routine passed 12 portable modes plus 2 real-FAT modes. Immutable combined evidence is `sdfat-evidence-20261115T1748.json`. RED and both initial environment/compiler failures remain separate logs; they were setup failures, not successful tests.

Follow-up qualification adds `sdfat_staging_fault_test.cpp` and `run_sdfat_staging.py`, registered in `run_all.py`. Both fixed slots are populated before the inactive slot is invalidated and reused, so reset truncates an existing file. For every observed staging block write (12) and seal block write (2), negative acknowledgement is injected after copying a prefix of 0, 1, 23, 24, 255, 511 or 512 bytes. All 84 staging and 14 sealing cases pass in normal and ASan/UBSan modes, with a fresh FAT volume remount proving the selected previous slot's full body remains readable. The integrated routine passes 12 portable modes and four actual-FAT modes; immutable evidence is `staging-integrated-evidence-20261115T1807.json`. This is a selected prefix-fault matrix, not every possible byte corruption, arbitrary power loss, or physical SD proof. Staging includes block-write errors emitted by truncation and file sync; `syncDevice()` negative acknowledgement and block-read failures are NOT yet qualified.
