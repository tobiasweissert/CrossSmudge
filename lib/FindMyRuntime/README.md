# Experimental firmware runtime integration

This is opt-in prototype code, not a certified Find My accessory. Local provisioning, a public advertising frame and an active controller do **not** prove Apple registration, native app visibility, report reception or account authorization.

## Owner flow (experimental firmware only)

1. Prepare the exact four-field `crosscub-findmy-v1` JSON with the separate host tool. Put the private file at SD `/crosscub-findmy.json`. The format has `schema`, 56 lowercase hex characters in `master_private_key_hex`, 64 lowercase hex characters in `primary_ratchet_seed_hex`, and `paired_at` as `YYYY-MM-DDTHH:MM:SSZ`. No account credentials are read by firmware.
2. After **each boot**, use the existing Clock Sync setting to obtain successful NTP synchronization. A settings bit or arbitrary system-clock assignment is insufficient. This first slice deliberately refuses the HAL's cached minute-only RTC as a second-precision source.
3. Open Settings → System → tap **Find My (experimental)** near the footer. This route only exists with `CROSSCUB_FINDMY_EXPERIMENTAL=1`. The supplied implementation has not been target-built or visually qualified; see gates below.
4. For a never-provisioned device select **Fresh provision + enable**, then select that same row again to confirm owner consent. Mere file presence never activates anything. For a previously provisioned device use **Enable existing checkpoint**, also with two selections. There is no automatic boot activation or automatic retry.
5. When the runtime reports tracking lock ready, enter the existing Quick Lock, or use a normal Sleep action/timeout: a healthy opted-in runtime replaces that particular sleep request with foreground Quick Lock retention. An automatically created tracking lock uses the existing long-Power unlock gesture. The e-ink image remains visible, frontlight turns off; this is **not** a qualified panel/SD rail-off or deep-sleep mode. Power draw is unmeasured.
6. Back exits this settings activity **without disabling** an enabled beacon, allowing normal reading followed by Quick Lock. The explicit Stop row disables it for the rest of the boot. Radio handoff likewise stops/latches it. Reboot, synchronize NTP and explicitly enable the existing checkpoint to start again.

A failed owner enable attempt latches for the boot. Reboot before another owner attempt, then sync NTP again. Never erase intent/checkpoint to retry. Core intentionally refuses a same-slot restart (`ReusedIndex`): wait for a later 15-minute slot, reboot/sync and use existing state, not fresh provisioning. A missing/corrupt/uncertain checkpoint or fresh-provision intent requires investigation; the runtime offers no reset/erase shortcut.

## Runtime boundary

- `src/findmy/Firmware.h`: `ownerEnableFresh`, `ownerEnableExisting`, `poll`, `standby`, `beforeAirDrop`, `beforeSleep`, `statusText`. Nonexperimental builds expose inert loop/sleep/handoff stubs and need no Core, BLE, NVS or Arduino link dependencies for those calls.
- `Runtime.h` runs the actual completed `::findmy::Core` through an injected `Radio` and `Persistence`. It polls and checks trusted time, monotonic leases, readiness, committed public key and native status. Same-key leases renew halfway through their lifetime, never after expiration. A continuously serviced slot boundary stops the old lease and admits only a newly committed index; a missed lease or long service gap fails closed.
- Each TTL is capped at 60,000 ms and remaining slot milliseconds. The firmware wrapper rechecks wall time/slot immediately before native publication after potentially blocking cryptography or checkpoint commits. A late commit may consume a checkpoint without broadcasting it; it cannot authorize a stale slot.
- `PrivateState.h` accepts at most 512 import bytes, exactly four unique unescaped string fields, strict lowercase hex and validated UTC calendar dates. Master/seed parser scratch and the SD input buffer are erased on scope exit. Production has no compiled provision keys or secret diagnostics.
- Checkpoints use an explicit 128-byte little-endian version-1 codec: version, identity/public coordinates, secret rolling seed, initial index, epoch, current index, last wall time and CRC32. NVS namespace `findmy-private` uses separate `intent` and `checkpoint` blobs. A fresh transaction checks both absent, commits/reads back intent, then invokes Core's explicit fresh initialization. Each checkpoint commit is an atomic NVS blob write, checked `nvs_commit`, exact length and byte readback before Core can publish. No raw C++ object layout is persisted.
- NVS's platform atomic/durable contract is relied on; no physical power-cut test was performed. CRC detects accidental corruption, not adversarial tampering. Neither SD nor NVS is claimed encrypted or anti-rollback protected. Preserve the private SD file and existing state and restrict owner access to storage/export services.
- Main polls before Quick Lock and all other early returns. A tracking-lock failure unlocks to a visible error rather than silently claiming a beacon. Healthy tracking suppresses repeated Quick Lock timeout sleep attempts. The original activity/SD teardown and real deep-sleep path remain intact when tracking is not admitted.
- AirDrop release calls explicit BLE stop/idle confirmation **before** Arduino WiFi release. It never guesses BLE ownership from WiFi mode. Handoff never auto-restarts the beacon. Main and the power HAL refuse deep sleep while ownership is uncertain. Native `begin()` is called by the actual wrapper, retaining its strong pre-setup BT anchor through linking.

## Verification and limits

Routine entrypoint: `python3 test/findmy/runtime/run.py`. It includes the original admission test, `check.py`'s production Core/firmware/private-codec/owner-activity compilations and all firmware modes, plus source hook guards and an extracted actual main timeout condition compiled with the production Quick Lock controller. Controlled HALs stand in for SD/NVS/clock/native radio/display/input; no RF occurs. UI tests exercise the actual activity's two-step tap consent and Back; they do not establish target rendering, painted-input freshness or touch geometry.

`python3 test/findmy/runtime/sdk_syntax.py` uses cached real Xtensa/S3 qio_opi headers without downloads/build/linking. Parent qualification resolved the initial missing-header probes using existing production SdFat/ArduinoJson and Arduino library headers read-only, and materialized pinned firmware header directories in this sparse checkout. Portable runtime/codec, actual firmware adapter and actual owner UI translation-unit syntax now pass with Sticky touch/USB capability flags. This is not a full main/HAL build or linked firmware. No simulator screenshots, full firmware ELF/link/retention-map check, physical standby current, power-cut durability, wake gesture, BLE coexistence/RF capture, registration or Apple account/report tests were performed.

Evidence: `/root/.hermes/task-state/crosscub-findmy-implementation/integration/`, including RED/GREEN logs, routine final log and cached target probe output. These are local controlled fixtures, not public accessory success evidence. PlatformIO, OTA, partitions, release publication and the completed Core/transport/sound libraries are outside this integration writer's scope.
